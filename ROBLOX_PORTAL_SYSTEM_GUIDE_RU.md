# Базовая система порталов + первое лицо (Roblox, R15)

Этот документ — практичный "скелет" для твоей игры в стиле **Portal** с упором на:

1. Базовые порталы (вход не до конца, частичный проход).
2. Рендер "окна" в другой портал + ограничение рекурсии до 5.
3. Обводка портала сквозь стены (как Portal 2).
4. Анимированные порталы (3 спрайт-слоя поверх вида в другой мир).
5. Первое лицо с видимым телом (R15), руками и синхронизацией анимаций в 3P.

## 2) Обязательные настройки объектов

1. Все поверхности для порталов:
   - Нормаль должна быть стабильной (без мешей с «кривой» коллизией на старте).
   - Материал/теги: например `CanPlacePortal=true` (через Attribute или CollectionService Tag).
2. Модель портала:
   - `Surface` Anchored=true, CanCollide=false, CanQuery=true.
   - `Trigger` Anchored=true, CanCollide=false, Transparency=1.
3. Коллизии:
   - Создай CollisionGroup `PortalGhost` для объектов, уже "внутри" перехода.
4. Камера:
   - `CameraMode = LockFirstPerson` для режимов, где обязательный 1P.

## 3) Базовая логика установки порталов

1. Клиент делает Raycast от камеры в центр/направление прицела.
2. Клиент отправляет на сервер:
   - тип портала (`Blue`/`Orange`),
   - hit position,
   - normal,
   - target Instance.
3. Сервер повторно валидирует Raycast (античит), проверяет:
   - дистанцию от игрока,
   - допустимость поверхности,
   - хватает ли места под эллипс/прямоугольник портала (несколько probe-ray вокруг центра).
4. Если валидно — сервер ставит/перемещает портал и шлёт `PortalState` всем клиентам.

## 4) Реалистичный проход: "можно войти не до конца"

Ключевая идея: не мгновенный телепорт всей модели, а **перенос через плоскость**.

1. Для персонажа храни состояние пересечения с `Trigger`:
   - какая доля тела зашла (по корневой части + нескольким контрольным точкам на туловище/ногах).
2. Перенос выполняй в момент, когда `HumanoidRootPart` пересекает плоскость портала в правильном направлении.
3. Пока игрок пересёк частично:
   - отображай клонированный "срез" персонажа на выходе (визуальный дубликат),
   - оригинал остаётся на входе,
   - дубликат синхронизируется по CFrame через матрицу портала.
4. После полного пересечения:
   - root переносится целиком,
   - линейная и угловая скорость преобразуются в систему координат второго портала.

Преобразование:
- `outCF = ExitPortalCF * Rot180Y * EntryPortalCF:ToObjectSpace(inCF)`
- Для velocity аналогично через `VectorToObjectSpace/VectorToWorldSpace`.

`Rot180Y` нужен, чтобы направление было как в Portal (вышел «вперёд» из второго).

## 5) Вид сквозь портал + рекурсивный предел 5

В Roblox нет "из коробки" stencil portal как в Source, поэтому рабочая схема:

1. Для каждого портала делай `ViewportFrame` в `SurfaceGui` на поверхности портала.
2. Во `ViewportFrame` рендерь прокси-сцену:
   - статические объекты-клоны,
   - персонажи-клоны,
   - отдельная Camera.
3. Камера портала считается из текущей camera игрока через пару порталов (та же формула трансформации).
4. Рекурсия:
   - хранить `maxDepth = 5`,
   - для глубины n рассчитывать последовательную трансформацию камер,
   - ниже 5 не рисовать (или рисовать упрощённо).

Практический компромисс для FPS:
- Полная рекурсия 0..2, а 3..5 — пониженное разрешение/частота обновления (например 15 FPS).

## 6) Обводка портала сквозь стены (Portal 2 style)

Подход в Roblox:

1. Создай копию контура портала (`HighlightProxy`):
   - тонкий неоновый MeshPart/Part по форме рамки.
2. Рендер поверх стен:
   - Используй `Highlight` (если подходит визуально),
   - либо Billboard/Surface-эффект на отдельном слое.
3. Логика показа:
   - если портал не в прямой видимости (Raycast от камеры в центр портала упирается в стену),
   - включай outline с мягкой альфой.
4. Цвета:
   - синий/оранжевый как у портала,
   - пульс по синусу для читаемости.

## 7) Анимация поверхности портала (3 спрайт-слоя)

Над рендером "другой стороны" наложи 3 текстурных слоя:

1. `DecalLayer1` — медленная рябь.
2. `DecalLayer2` — средняя скорость, противоположный скролл.
3. `DecalLayer3` — быстрые энергетические шумы.

Для каждого слоя крути UV/Offset по времени, добавляй небольшую модуляцию прозрачности.

Рекомендация:
- Центральную часть делай более прозрачной,
- края — более яркие, чтобы форма портала читалась.

## 8) Первое лицо с видимым R15 телом

### Цели
- В 1P игрок видит своё тело/ноги/руки.
- Руки направлены за взглядом камеры (как Source).
- Кастомная анимация рук работает в 1P и видна в 3P.

### Реализация

1. **Не скрывай тело локально полностью**:
   - вместо классического "голова invisible + всё off" оставляй тело видимым.
2. Голова в 1P:
   - либо скрывай только геометрию головы локально,
   - либо смещай камеру чуть впереди Head, чтобы не видеть "внутренности".
3. Руки:
   - используй Motor6D-поправки от yaw/pitch камеры каждый кадр (`RenderStepped`).
   - ограничь pitch (например -80..80), добавь сглаживание (lerp/spring).
4. Анимации:
   - отдельный `AnimationController`/Humanoid track для рук,
   - тот же track проигрывай на полноценном риге (или реплицируй параметры), чтобы в 3P руки двигались так же.
5. Тело/голова в 3P:
   - поворот torso/neck к направлению взгляда игрока с лимитами углов.

## 9) Синхронизация персонажа через порталы

Чтобы через портал в 3P всё выглядело корректно:

1. В `PortalRenderer.client.lua` делай клон всех персонажей для ViewportFrame.
2. Для каждого кадра:
   - копируй позы Motor6D,
   - применяй трансформацию portal-space.
3. Для локального игрока:
   - в 1P можешь использовать упрощённый рендер рук в Viewport,
   - но для 3P-представления через портал нужен полный риг.

---

## 10) Управление (базово)

- ЛКМ: синий портал.
- ПКМ: оранжевый портал.
- R: очистить оба портала (или только свой).
- (Опционально) Q: быстрый swap активного цвета.

UI-индикаторы:
- белый прицел = валидная поверхность,
- красный = нельзя поставить.

---

## 11) Минимальный `PortalConfig` (поля)

- `MAX_RECURSION = 5`
- `PORTAL_SIZE = Vector2.new(w, h)`
- `MAX_PLACE_DISTANCE`
- `OUTLINE_WHEN_OCCLUDED = true`
- `PORTAL_LAYER_SPEEDS = {0.05, -0.12, 0.25}`
- `FIRST_PERSON_BODY_VISIBLE = true`
- `ARM_AIM_SMOOTH = 0.18`
- `PARTIAL_CROSSING_POINTS = {...}`

---

## 12) Оптимизация (важно)

1. Обновляй ViewportFrame не каждый кадр для дальних/невидимых порталов.
2. Используй object pooling для клонов персонажей.
3. Ограничь число активных "портальных" источников света.
4. Для уровня редактора добавь упрощённый режим предпросмотра порталов.

---

## 13) Порядок внедрения (чтобы не утонуть)

1. Поставка/валидация порталов (без рендера).
2. Телепорт + перенос скорости.
3. Частичный вход (дубликат/срез).
4. Рендер окна портала (без рекурсии).
5. Рекурсия до 5 с деградацией качества.
6. Outline сквозь стены.
7. 3-слойная анимация поверхности.
8. Полировка 1P/3P рук и головы.

---

## 14) Частые ошибки

- Телепорт без преобразования velocity (ломает физику прыжков).
- Перемещение персонажа только по root без учёта позы (визуальный "рывок").
- Попытка полной рекурсии в 60 FPS на слабых устройствах.
- Отсутствие серверной валидации постановки портала.
